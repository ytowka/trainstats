Я разработал такую архитектуру

При вводе изменений в приложении:
1) Выставить флаг, что произошло изменение
- На клиенте должен быть флаг, означающий, что есть несинхронизированные изменения
- Вместе с флагом, должна храниться некая таблица с id сущностем, которые должны быть отпавлены на сервер

2) Сохранить изменения локально

Далее если есть соединение с сервером
3) Отправить измененные сущности на сервер
4) Сервер сохраняет сущности к себе в базу данных. (На этом этапе сервер не хранит историю, а только обновляет свой экземпляр базы)
5) Сервер отдает тэг изменений, сохраняем его на клиенте
6) Убираем флаг синхронизации, и очищаем таблицу

Заход в приложение:
1) Проверка актуальности
   -Должен быть некий тэг, по которому можно понять, синхронизированы ли изменения.
   -Сервер должен иметь таблицу, с тэгами клиентов

1.1) У клиента нет тэга
- Новая ссесия, загрузить все с сервера

1.2.1) У клиента есть флаг pending
- Отправляем изменения на сервер

1.2.2) client tag == server tag ?
true: Данные актуальны
false: Предложить клиенту загрузить данные
