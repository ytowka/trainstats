# Вариации упражнений

Статус: реализовано в Android UI и общей KMP-логике.
Решения уточнены 12 октября 2026 года.

## Суть и модель

У упражнения можно создать именованные вариации. Например, у тяги верхнего блока — «Узкая ручка» и «Широкая ручка».

- `variationId = null` означает обычную вариацию. Отдельная запись в справочнике для неё не создаётся.
- Вариация принадлежит конкретному упражнению. Название уникально **внутри упражнения** при сравнении после `trim + lowercase`.
- Одинаковые названия у разных упражнений допустимы. «Узкая ручка» и « узкая ручка » у одного упражнения считаются дубликатами.
- Пользователь может создать вариацию с названием «Обычный». Она имеет собственный ID и отличается от `null`. Специального запрета, переименования или дополнительной подписи для такого совпадения не требуется: в селекторе допустимы два пункта «Обычный».
- В БД вариация привязана к каждому подходу, поскольку подходы хранятся независимо.
- В presentation и ViewModel у блока упражнения одна общая вариация. Блок формируется из **последовательных подходов с одинаковой парой `(exerciseId, variationId)`**.
- Соседние блоки с одинаковой парой после повторной загрузки тренировки объединяются. Подходы одного упражнения с разными вариациями остаются в разных блоках.

Сейчас группировка выполняется в `Workout.toModel()` в `features/workout/ui/WorkoutModel.kt` по одному `exerciseId`. При реализации нужно добавить `variationId` в условие группировки и передавать вариацию блока каждому его подходу при сохранении.

## Создание и редактирование упражнения

- В конце редактора, над кнопками «Удалить» и «Сохранить», разместить «+ Добавить вариацию».
- Нажатие добавляет в этом же редакторе редактируемую строку списка вариаций.
- При добавлении первой именованной вариации список также показывает нередактируемый пункт «Обычный» без кнопки удаления. Он соответствует `null` и не создаёт запись в справочнике.
- Названия существующих вариаций можно изменять.
- У каждой строки есть иконка корзины. По нажатию открывается bottom sheet с предупреждением: все подходы с этой вариацией станут обычными (`variationId = null`).
- Подтверждение корзины только отмечает вариацию для удаления в текущем редакторе.
- **Создание, переименование и удаление применяются вместе по кнопке «Сохранить».** Закрытие редактора без сохранения отменяет эти изменения, включая подтверждённое удаление.
- При сохранении удаление вариации затрагивает все связанные подходы, включая историю тренировок. Переименование сохраняет ID вариации.

## Выбор и создание вариации в тренировке

- По умолчанию новый блок упражнения имеет обычную вариацию (`null`).
- Нажатие на название упражнения открывает bottom sheet выбора вариации.
- Список выглядит аналогично блоку вариаций в редакторе упражнения. Здесь можно выбрать вариацию или создать новую; переименование и удаление выполняются в редакторе упражнения.
- В списке всегда доступна обычная вариация (`null`).
- Вариации представлены карточками с радиокнопками; текущая вариация выделена цветом и рамкой.
- Выбор меняет вариацию **всего текущего блока**, включая уже введённые подходы. Новые подходы в этом блоке получают ту же вариацию.
- Если `variationId != null`, название вариации отображается под названием упражнения серым текстом меньшего размера. Для `null` подпись отсутствует. Проверяется ID, а не текст названия, поэтому пользовательское «Обычный» отображается.
- Изменение вариации блока сохраняется через существующее автосохранение тренировки (`WorkoutSaver`), с сохранением его debounce и финального сохранения при завершении жизни редактора.

Создание из тренировки:

1. Пользователь нажимает «Добавить вариацию» и вводит название.
2. По кнопке «Создать» вариация сразу сохраняется в справочник упражнения.
3. Созданная вариация выбирается для всего текущего блока, bottom sheet закрывается.
4. Выбор сохраняется в тренировке через её автосохранение.

Если закрыть окно до нажатия «Создать», введённый текст отбрасывается и вариация не создаётся.

## История упражнения

- По умолчанию история показывает все вариации упражнения.
- Внутри каждой записи истории подходы отображаются блоками по паре `(exerciseId, variationId)` с сохранением порядка.
- В каждом блоке название вариации выделено заметным заголовком с нижним отступом перед подходами; для `null` подпись отсутствует.
- Добавить чекбокс **«Только текущая вариация»**, по умолчанию выключенный.
- При включении остаются только подходы с вариацией блока, из которого открыта история. Если текущая вариация — `null`, показываются только обычные подходы.

## Статистика

### Общий фильтр вариаций

- Фильтр нужен **на обоих графиках: показателей и частоты**.
- Если у выбранного упражнения есть именованные вариации, между упражнением и показателем показать dropdown в общем стиле фильтров: подпись «Вариация», выбранное значение слева и поворачивающаяся стрелка справа. Раскрытое меню занимает всю ширину блока фильтров и содержит чекбоксы вариаций, обычной вариации (`null`) и «Все».
- При выборе упражнения изначально включены все его вариации, включая `null`.
- Выбор общий для двух вкладок: переключение между показателями и частотой сохраняет чекбоксы.
- При переходе к другому упражнению включаются все вариации нового упражнения.
- «Все» включает весь список; снятие этого чекбокса снимает всё.
- Можно снять все чекбоксы. Вместо данных показать пустое состояние «Выберите вариацию».

### График показателей и рекорд

- Выбранные вариации фильтруют подходы; результат отображается **одним общим графиком** без отдельных линий по вариациям.
- Сначала отбираются подходы выбранного упражнения и выбранных вариаций, затем серии нумеруются заново внутри каждой тренировки в порядке подходов, сквозным образом по всем её блокам выбранных вариаций.
- Пример: обычный хват занимал подходы №1–2, узкий — №3–4. При выборе только узкого хвата его подходы становятся сериями №1–2.
- Подход с нулевыми повторениями не создаёт точку, но занимает свой номер серии: после исключения таких точек серии повторно не нумеруются.
- «Максимум» — одна точка на тренировку, рассчитанная среди подходов выбранных вариаций. Например, 60 кг обычным хватом и 50 кг узким при выборе обеих дают максимум 60 кг.
- Карточки выбранного подхода и рекорда показывают название вариации самого подхода, если его `variationId != null`, в том числе для именованного «Обычный».
- **Рекорд учитывает фильтр вариаций**, но остаётся рекордом за всё время, независимо от видимого диапазона дат и включённых серий.
- Пример: рекорд обычным хватом — 100 кг, узким — 70 кг. При выборе только узкого показывается 70 кг; при включении всех — 100 кг.
- Существующие формулы веса, повторений и объёма, обработка отсутствующего и нулевого веса, исключение архивных тренировок и правила разрешения равных результатов сохраняются.

### График частоты

- В режиме «Упражнение» учитываются только подходы выбранного упражнения и выбранных вариаций с конечным положительным суммарным числом повторений.
- Тренировка учитывается, если содержит хотя бы один такой подход, и считается **один раз**, даже если в ней несколько выбранных вариаций.
- Метрика числа подходов считает только подходы, прошедшие фильтр.
- Итоги за всё время также учитывают фильтр вариаций.
- В режиме **«Все тренировки»** фильтр вариаций скрыт и не ограничивает расчёт: учитывается вся активность по существующим правилам.
- При возвращении к режиму «Упражнение» восстанавливаются выбранные чекбоксы вариаций.
- Существующие календарные интервалы, пустые интервалы и расчёты с учётом часового пояса сохраняются.

## БД и границы реализации

- Создать таблицу вариаций с полями `id` (UUID, уникальный среди всех вариаций), `exerciseId` (foreign key к упражнению), `name`, `isDefault` (по умолчанию false).
- Обеспечить уникальность нормализованного названия **внутри упражнения**, а не глобальный `unique(name)`. Use cases приводят сохраняемое название к `trim + lowercase + capitalize`, в том числе для русских названий. В БД хранится только `name`, уникальный индекс — `(exerciseId, name)`; отдельное поле нормализации не нужно.
- В `ExerciseSetEntity` добавить nullable `variationId` с foreign key и `ON DELETE SET NULL`.
- Последовательно сохранять упражнение и его вариации в DataSource, в общей транзакции, включая перевод подходов удалённых вариаций в `null`. Для обмена именами двух вариаций временно освобождать уникальные имена в этой же транзакции.
- Селектор предлагает вариации только текущего упражнения; дополнительной проверки принадлежности в WorkoutDao нет. Выбор передаёт ID и название в состояние группы, без подписки WorkoutViewModel на справочник.
- Согласовать состояние открытого редактора и отложенное автосохранение с удалением вариаций: устаревший `variationId` не должен восстанавливать удалённую вариацию или приводить к ошибке сохранения.
- По решению при ревью миграции не поддерживать на данном этапе: версия Room — 4, оба builder используют `fallbackToDestructiveMigration(true)`. Обновление старой базы пересоздаёт её; перенос данных выполняется экспортом и импортом. Сохранить исторические tracked schemas и добавить актуальную.
- Entities разместить в `:common-db-api`, DAO — в `:common-db`, модели, use cases и ViewModel — в `:shared`, экраны — в `:ui-compose`. Сохранить Compose-free границы shared-логики.
- Передавать вариации через чтение и сохранение тренировок, историю упражнения, расчёты статистики и read-only детали тренировки. В деталях использовать ту же группировку и подписи вариаций.

## Импорт и экспорт

Экспорт переносит историю тренировок и использованные вариации. Отдельный раздел справочника не нужен: **созданные, но не использованные в подходах вариации не обязаны переживать экспорт → импорт**.

Формат заголовка блока упражнения:

```text
тяга верхнего блока
тяга верхнего блока $ узкая ручка
```

- Разделитель названия упражнения и вариации — **`$`**.
- При `variationId = null` экспортировать только название упражнения, как в старом формате.
- При наличии вариации экспортировать `название упражнения $ название вариации`.
- При экспорте нового блока учитывать пару `(exerciseId, variationId)`, чтобы разные вариации одного упражнения не терялись.
- Импорт без разделителя сохраняет прежний смысл: обычная вариация (`null`). Старые файлы остаются совместимыми.
- Если после `$` пустая строка или только пробелы, считать вариацию `null`, **а не ошибкой импорта**.
- При импорте искать существующую вариацию по `trim + lowercase` **внутри соответствующего упражнения**. При отсутствии создавать новую и связывать с импортируемыми подходами.
- Название «Обычный» после `$` означает пользовательскую именованную вариацию, а не `null`.
- **Доработать парсер, чтобы он принимал цифры и специальные символы в названиях упражнений и вариаций**, например «Ручка 45°», скобки и `::`. Текущий ограничительный regex названий требуется пересмотреть.
- Буквальный `$` внутри названия записывается как `$$`. Первый одиночный `$` отделяет вариацию; парсер восстанавливает удвоенные символы в обоих названиях. Например: `тяга $$ блок $ ручка $$ 45°`.

## Сценарии проверки при реализации

- Выбор вариации меняет все подходы текущего блока и сохраняется после повторного открытия тренировки.
- Соседние подходы одного упражнения с разными вариациями не склеиваются; с одинаковой парой склеиваются после загрузки.
- Отмена редактора упражнения отменяет создание, переименование и подтверждённое удаление вариаций. «Сохранить» применяет всё вместе.
- Удаление вариации переводит её исторические подходы в `null` и корректно взаимодействует с открытым редактором и автосохранением.
- Создание вариации из тренировки сохраняет её в справочник, выбирает для блока и закрывает окно; закрытие до «Создать» ничего не создаёт.
- Дубликаты с отличиями в регистре и пробелах запрещены внутри упражнения, одинаковые названия у разных упражнений допустимы. Пользовательское «Обычный» допустимо и отличается от `null`.
- История подписывает вариации блоков и фильтруется чекбоксом «Только текущая вариация», включая текущую `null`.
- Фильтрация показателей пересчитывает номера серий, максимум и рекорд; нулевые повторения сохраняют место в нумерации.
- Частота считает тренировку один раз и только подходящие подходы; фильтр действует на итоги за всё время, сохраняется между вкладками и игнорируется в режиме «Все тренировки».
- Снятие всех чекбоксов показывает «Выберите вариацию»; переход к другому упражнению включает все его вариации.
- Проверить импорт старого формата, нового формата с `$`, пустого суффикса, названий с цифрами и символами, повторное использование существующей вариации и сохранение различий между блоками после экспорт → импорт.
- Проверить пересоздание базы предыдущей версии и сохранение данных в новой схеме; перенос истории проверять экспортом и импортом.


## Дефолтная вариация и быстрый выбор

- В редакторе звезда назначает единственную дефолтную именованную вариацию. Звезда у «Обычного» снимает все `isDefault`; отсутствие флагов означает обычную вариацию. Удаление дефолтной вариации также возвращает этот режим.
- Выбор дефолта сохраняется вместе с остальными черновиками только по «Сохранить»; закрытие отменяет изменения. Создание вариации из тренировки не меняет дефолт.
- «Обычный» отображается серой строкой той же высоты, что и поля имён. Он не редактируется и не удаляется. Интервал между строками — 4 dp.
- Удаление именованной вариации — свайп влево с подтверждением. Для средств доступности есть действие удаления.
- Новая пустая строка не показывает ошибку сразу. Валидация отображается после редактирования имени или попытки сохранения.
- В выборе упражнения под карточкой есть горизонтальный список: обычная и именованные вариации. Если именованных вариаций нет, список чипов скрыт целиком. Нажатие добавляет упражнение с выбранной вариацией за один шаг. Нажатие на саму карточку использует дефолт; явный выбор «Обычного» всегда даёт `variationId = null`.
- В основном списке упражнений карточки показывают тот же горизонтальный список с отметкой дефолтной вариации. Чипы служат подписями; нажатие на карточку открывает редактор упражнения. Если именованных вариаций нет, чипы скрыты.
